Projet 03 — Systèmes

Installation de Windows 10
en machine virtuelle.

Procédure complète d'installation et de configuration d'un poste Windows dans VirtualBox — de la création de la VM à la validation réseau, avec un incident réel rencontré et résolu.

VirtualBox Windows 10 ISO Microsoft BIOS / SVM Configuration réseau
Contexte

Objectif : installer et configurer un poste Windows 10 dans VirtualBox, en documentant chaque étape comme une procédure technique reproductible — le cœur du métier de support : déployer, configurer, valider.

La virtualisation permet de créer des environnements de test sans risque pour la machine hôte. C'est un outil fondamental en BTS SIO pour tester des configurations réseau, des déploiements et des procédures de maintenance.

Procédure

Installation étape par étape.

01

Création de la machine virtuelle

Dans VirtualBox, cliquer sur Nouvelle et renseigner les paramètres :

  • Nom : WinTest01
  • Type : Microsoft Windows — Version : Windows 10 (64-bit)
  • RAM allouée : 2048 Mo
  • Disque dur virtuel : Créer — VDI — Dynamique — 25 Go
02

Montage de l'ISO Windows

Avant de démarrer, attacher l'ISO au lecteur optique virtuel :

  • Sélectionner la VM → Configuration → Stockage
  • Cliquer sur le lecteur CD vide (Port SATA 1)
  • Icône disque → Choisir un fichier de disque → sélectionner le .iso
⚠️

Vérifier que l'ISO est bien attaché avant de démarrer — sinon la VM démarre sur un disque vide et affiche une erreur de boot. Sur la vue Détails, le Port SATA 1 doit afficher le nom du fichier .iso et non « Vide ».

03

Configuration réseau de la VM

Choisir le mode réseau selon le besoin :

  • Accès par pont (Bridge) : la VM obtient une IP du même réseau que l'hôte — idéal pour tester la connectivité réelle
  • NAT : la VM accède à internet via l'hôte — simple mais isolée du réseau local
  • Réseau interne : VMs isolées entre elles — pour des labos sans internet
💡

Choix pour ce projet : Accès par pont sur la carte Wi-Fi de l'hôte (Intel Wi-Fi 6 AX200), pour que la VM reçoive une vraie IP du DHCP de la box et soit visible sur le réseau local. Vérification à l'étape 06.

04

Installation de Windows 10

Démarrer la VM — l'assistant d'installation se lance :

  • Langue et format horaire → Suivant → Installer maintenant
  • Clé de produit → Je n'ai pas de clé de produit (mode évaluation)
  • Édition : Windows 10 Pro
  • Type d'installation : Personnalisé (installation propre)
  • Sélectionner le disque virtuel de 25 Go → Suivant → copie des fichiers (10-15 min)
05

Configuration initiale (OOBE)

Au premier démarrage, Windows lance l'assistant de configuration :

  • Région : France — Clavier : Français
  • Compte : Compte hors connexion (pas de compte Microsoft requis)
  • Utilisateur : ex. Technicien + mot de passe
  • Paramètres de confidentialité : tout désactiver pour une VM de test
06

Validation réseau depuis la VM

Ouvrir cmd dans la VM et dérouler les tests de connectivité :

  • ipconfig → la VM a bien reçu une IP du DHCP
  • ping 192.168.1.1 → la passerelle répond
  • ping 8.8.8.8 → l'accès internet fonctionne
  • ping [IP de l'hôte] → VM et hôte communiquent
💡

Si la VM et l'hôte se pingent mutuellement, le mode pont fonctionne : la VM est intégrée au réseau local comme un vrai poste. Ce test fait le lien avec le projet 01.

Incident rencontré

Erreur au premier démarrage de la VM.

Au lancement de la machine virtuelle, VirtualBox a refusé de démarrer avec l'erreur suivante :

VirtualBox — Erreur au démarrage de WinTest01
VM Name: WinTest01

Not in a hypervisor partition (HVP=0) (VERR_NEM_NOT_AVAILABLE).
AMD-V is disabled in the BIOS (or by the host OS) (VERR_SVM_DISABLED).

Result Code : E_FAIL (0x80004005)
Component : ConsoleWrap
Interface : IConsole

Résolution en appliquant la même méthode de diagnostic que sur le terrain :

01 — Observer

Lire le message

L'erreur VERR_SVM_DISABLED indique explicitement que AMD-V est désactivé dans le BIOS ou bloqué par l'OS hôte.

02 — Diagnostiquer

Identifier la cause

AMD-V (appelé SVM chez AMD) est la virtualisation matérielle du processeur. Désactivée par défaut sur de nombreuses cartes mères.

03 — Corriger

Activer le SVM

Redémarrage → BIOS/UEFI → option SVM Mode (section CPU) passée sur Enabled → sauvegarde et redémarrage.

04 — Documenter

Tracer l'incident

Erreur, cause et solution consignées dans cette page — la VM démarre normalement après correction.

💡

Ce que cet incident illustre : un message d'erreur bien lu contient souvent sa propre solution. La méthode observer → diagnostiquer → corriger → documenter, issue de la maintenance industrielle, s'applique directement au support informatique.

Bilan

Ce que ce projet m'a appris

  • Créer et configurer une machine virtuelle dans VirtualBox
  • Diagnostiquer et résoudre un blocage de virtualisation matérielle (SVM/AMD-V dans le BIOS)
  • Installer Windows 10 depuis une ISO officielle Microsoft
  • Comprendre les modes réseau de VirtualBox (NAT, pont, réseau interne)
  • Valider le fonctionnement réseau d'un poste après installation
  • Rédiger une procédure technique reproductible, incident compris
