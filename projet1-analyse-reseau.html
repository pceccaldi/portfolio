Projet 01 — Réseau

Analyse du réseau
d'un poste Windows.

Identification de la configuration réseau d'une machine, tests de connectivité et analyse du chemin réseau — avec la même méthode de diagnostic que sur le terrain.

Windows 10/11 ipconfig ping tracert nslookup
Contexte

Objectif : comprendre et documenter la configuration réseau d'un poste Windows avec les commandes natives. Identifier l'IP, la passerelle, le DNS, tester la connectivité et analyser le chemin réseau.

Ce projet illustre une démarche de diagnostic réseau de premier niveau — ce que ferait un technicien support face à un problème de connectivité. Toutes les commandes sont exécutées dans l'invite de commandes Windows (cmd).

Démarche

Méthode en 4 étapes.

ÉTAPE_01

Identifier

Relever la configuration IP du poste avec ipconfig /all.

ÉTAPE_02

Tester local

Vérifier la connectivité vers le loopback et la passerelle.

ÉTAPE_03

Tester externe

Ping vers internet et résolution DNS.

ÉTAPE_04

Analyser

Tracert pour visualiser le chemin réseau complet.

Étape 01 — ipconfig /all

Identification de la configuration IP.

La commande ipconfig /all affiche l'ensemble des informations réseau de la machine : adresse IP, masque, passerelle, serveurs DNS et adresse MAC.

cmd — ipconfig /all
C:\Users\Pierre-François> ipconfig /all

Étape 02 — ping

Tests de connectivité progressifs.

Le ping envoie des paquets vers une adresse et mesure si elle répond. La logique de diagnostic : tester du plus proche au plus lointain pour localiser précisément où se situe un éventuel problème.

cmd — tests ping
— Test 1 : loopback (la machine elle-même) —
C:\> ping 127.0.0.1
Réponse de 127.0.0.1 : octets=32 temps<1ms TTL=128
→ La pile TCP/IP fonctionne sur ce poste.

— Test 2 : passerelle (la box) —
C:\> ping 192.168.1.1
Réponse de 192.168.1.1 : octets=32 temps=2ms TTL=64
→ Le réseau local fonctionne.

— Test 3 : internet (IP directe, sans DNS) —
C:\> ping 8.8.8.8
Réponse de 8.8.8.8 : octets=32 temps=14ms TTL=118
→ L'accès internet fonctionne.

— Test 4 : résolution DNS —
C:\> ping google.com
Réponse de 142.250.75.206 : octets=32 temps=12ms TTL=118
→ Le DNS traduit bien les noms de domaine en IP.

Intérêt de cette progression : si le test 2 échoue, le problème est local (câble, Wi-Fi, carte réseau). Si le test 3 échoue mais pas le 2, le problème vient de la connexion internet. Si seul le test 4 échoue, c'est un problème DNS. Chaque étape isole une couche du réseau.

Étape 03 — tracert

Analyse du chemin réseau.

La commande tracert affiche chaque routeur traversé entre le poste et la destination. Elle permet d'identifier précisément où une connexion se dégrade ou se bloque.

cmd — tracert google.com
C:\> tracert google.com

Détermination de l'itinéraire vers google.com [142.250.75.206]

1 1 ms 1 ms 1 ms 192.168.1.1 ← box / routeur local
2 8 ms 7 ms 8 ms 10.x.x.1 ← premier routeur du FAI
3 11 ms 10 ms 11 ms 81.x.x.x ← backbone FAI
4 12 ms 12 ms 11 ms 74.125.x.x ← infrastructure Google
5 13 ms 12 ms 13 ms 142.250.75.206 ← destination atteinte

Itinéraire déterminé.
Bilan

Ce que ce projet m'a appris

  • Lire et interpréter une configuration réseau complète (IP, masque, passerelle, DNS)
  • Distinguer un problème local d'un problème internet grâce aux tests progressifs
  • Comprendre le rôle du DHCP, du DNS et de la passerelle
  • Utiliser tracert pour localiser un point de blocage sur le chemin réseau
  • Documenter une analyse technique de façon structurée et reproductible
